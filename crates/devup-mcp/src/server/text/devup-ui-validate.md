Validate DevupUI TSX against a project's real devup.json: unknown $token references, hardcoded colors/lengths, unknown props on Box/Flex/Text/Center/Grid/Image, and non-static values inside css()/globalCss()/keyframes() calls. `ok` is decided by severity, not by count: errors fail, and `strict: true` also fails warnings. Hardcoded values with exact matching tokens are warnings with token advice; unmatched values are info without token advice and never fail strict mode. `okReason` distinguishes clean, clean-unverified-tokens, info-only, warnings-only, warnings-and-info, strict-warnings, and error-violations; `clean-unverified-tokens` means no violation was found but no devup.json was resolved, so the $token references this code makes were never checked. With paths or files, each source is checked against the nearest devup.json above it, so one call over a repository of several apps uses each app's own theme; `tokens.scopes` lists each theme with its file and reference counts, `tokens.verification` is verified, partial or skipped, and files no devup.json governs are named in `themeGuardrail.unverifiedPaths` and never counted as checked (`themeAvailable` and `tokens.unknownTokenCheckRan` are true only when every file was checked). A module-level const of the same file holding a literal or a keyframes()/css() name is a static value inside css()/globalCss()/keyframes() (`css({ animationName: spin })`); imports, parameters and call results remain `runtime-value`. A single tsx has no location, so at a repository root with several themes its tokens stay unverified unless sourceName gives its relative path (apps/front/src/Hero.tsx): the nearest devup.json above that location is then used and named in `tokens.devupJson`; the named file is never opened. Supplying neither tsx nor files is rejected rather than answered `clean`. Structural rules (file-placement, one-component-per-file, client-boundary, inline-style, react-query-states) run only in `files` bundle mode; framework-required default exports (page, layout, loading, error, not-found, template, and the metadata conventions) are exempt from file-placement. With projectRoot, a maskImage whose public SVG paints more than one colour warns `multicolor-mask` (use <Image src>), and a root-relative asset URL (src or url(...)) with no file under any public directory is an error (`asset-missing`), always failing `ok`. `themeNotes` summarizes each encountered empty token category once. Site completeness: an interactive element (as=a/button, Link, button, onClick) with no _hover or _focusVisible is a warning (interactive-states), one with no focus style is a warning (focus-style), too much motion - over 400ms, scale above 1.05, infinite - is a warning (too-much-motion), an icon-only button without aria-label is a warning (icon-button-label); a button with no _active, a _hover with no transition, motion with no _motionReduce and a nav link with no aria-current are info (button-active, hover-transition, motion-reduce, nav-current); a page or layout with no metadata export is a warning (page-metadata, files mode), and with projectRoot an app with no icon or favicon is a warning (app-icon). Navigation rules also report unmapped action candidates/accessibility warnings, missing static App Router href errors when projectRoot inventory is complete, and literal active-state info. Dynamic hrefs/custom routing and incomplete bundles remain unverified. Optional renderedHtml reports captured anchor counts separately from source coverage; neither proves runtime behavior. `checkedTokens` counts references and `availableTokenCount` counts definitions; they are not a ratio. Default detail is summary: compact findings merged by source/rule/message (count for repeats), at most 100 rows, severity counts and layoutRiskCount. Use detail:"full" for all diagnostics including navigation and verificationScope. paths accepts files or recursive directories inside projectRoot, exclusive with tsx/files, up to 512 source files and 8 MiB; it runs bundle structural checks with the disk themes (nearest devup.json per file) and reports pathsRead. Directory reads skip generated and hidden directories. Supplied files retain their 64-file/1 MiB limits and never read their theme from disk; several supplied devup.json files each govern their own directory.

Entrance motion, from source alone (warnings): `ssr-hidden-reveal` - an always-rendered motion.* element starts at opacity 0 (initial object, or a named variant declared on the same element), so server markup is invisible until JavaScript runs; elements inside AnimatePresence or a conditional render are client-mounted and exempt. `reveal-replays` - whileInView without viewport={{ once: true }}; an in-view hook (useInView) with no once/triggerOnce option is the same finding at info, since its purpose is not visible. `stagger-too-long` - staggerChildren, or delay: index * step, above 150ms per item. Components built with motion.create()/motion() in the same file are read like motion.* elements. `reveal-moves-background` - the whileInView element also paints a background, so the section paint moves with its content. `motion-without-reduced-motion` (paths/files only) - entrance motion while no validated source, nor projectRoot/src in paths mode, handles reduced motion (a call or prop such as useReducedMotion, MotionConfig reducedMotion, _motionReduce, or a prefers-reduced-motion media rule; a comment or an unused import does not count). Trigger timing, intermediate frames, re-entry, history and image loading are runtime evidence, not checked here.

Parsed globalCss anchor rules in the supplied bundle suppress this warning; paths mode also checks projectRoot/src within the source read limits. Hover-only decoration does not reset the resting state. `marquee-static` is informational: long single-line JSX text with at least three repeated separators and no keyframes/animation in the same file suggests a static scrolling strip.
