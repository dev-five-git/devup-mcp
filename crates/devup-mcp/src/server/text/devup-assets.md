Inventory public assets and exact source/seed URL references, then plan, dry-run, apply or roll back a reviewed asset migration. `projectRoot` is required; all paths remain inside the configured output policy. `inventory` discovers public directories or accepts explicit `publicRoots`; `referencePaths` bounds authored source and seed scanning. Symlinks, syntax gaps and dynamic image expressions remain explicit unresolved evidence. `dynamicUsageProven` and `liveDatabaseVerified` are always false.

`plan` requires explicit `renames: [{publicRoot?,from,to}]`; byte-identical files can share a meaningful destination. Different bytes never overwrite a destination. `dryRun` defaults true. `plan` with `dryRun:false` persists a content-bound plan under `.devup/asset-migrations/<id>/plan.json`; it does not change assets or source. `apply` and `rollback` require that `planPath`; first dry-run, then use `dryRun:false`. Changes, digests, exact reference spans and registry updates are rechecked. A stale plan or edited rollback target is refused. Local writes and optional source retirement share one output transaction and a guarded rollback journal.

Old assets remain compatibility aliases by default. `retireSources:true` additionally requires one explicitly selected public root, explicit reference paths, no unresolved dynamic references and no pending DB SQL. This bounded static check does not prove arbitrary runtime usage. Prefer retaining aliases when API/CDN/DB or dynamic callers may still use them.

Optional `databaseReferences` declares a PostgreSQL scalar-text URL adapter: `{snapshotPath,schema?,table,keyColumn,urlColumn}`. The project-relative snapshot is a JSON array of `{key:string|number,url:string}` rows exported from that DB. Planning produces exact per-row forward SQL, verification SQL and old-value guarded rollback SQL. Apply writes those artifacts privately; it never connects to or changes a live DB, and never pretends a snapshot proves current DB state. JSON, arrays, rich text, computed URLs and cross-database atomic commits are unsupported. Review/run SQL separately, verify results, and retain old public aliases through that process. Local rollback does not roll back the DB.

Responses use `responseOffset` and `responseLimit` pages and adapt the page size to a 200 KB JSON budget. The persisted plan contains the full inventory and mutation digests. Quoted JS/TS/JSX/TSX, JSON and SQL URL literals and simple CSS `url()` references are supported; source templates, dynamic expressions, rich text and compound srcSet values remain unresolved rather than being guessed. Query strings and fragments on an exactly matched source URL are preserved. Asset renaming preserves encoding; converting PNG/WebP or other formats requires a separate export. When a migration includes DB SQL, local rollback retains canonical assets and registry records so independently applied DB changes cannot create missing URLs.

Figma exports with anonymous or collision-generated names are quarantined. They return `assetQuarantine.published:false` and no TSX/public/registry writes. Bytes and a receipt are retained in an authorized private `.devup/asset-staging/` directory; with a public-only write scope they stay in the retained artifact instead of creating a publicly served quarantine. Read the required naming edits, set meaningful `assetRequests.outputPath` values, and reproject the same artifact. That successful export commits assets, registry and application source together. Expired artifacts must be reacquired from Figma.
