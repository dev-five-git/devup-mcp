Project intake and supervisor: intake | draft | confirm | status | assume | defer | split.

Read Jira/epic children, Figma and devup_project_context all scopes first; pass source-labelled evidence. intake asks work type, optional sources, goal and parts through the runtime question tool. draft records feature-specific rounds and ERD, merges shared question topics, and reports added/changed/kept/removed records in changeSummary. Shared site facts are forwarded to open screen-plan questions; explicit answers take precedence. confirm requires all answers and the Figma screen plan when applicable, writes vespertide models/*.json transactionally, and returns executable recovery for missing answers.

split creates a dependency DAG and .devup/units/<id>.md briefs: supervisor-owned shared/table foundations, parallel domain workers, then supervisor integration. Features sharing screen section/menu or entities form one worker owning API, client and pages together; static domains only own front work. Repeated screen parts become sharedParts in stage 0. Each table has one model owner. Briefs prioritize answers and decisions over original scope and filter routes by owned screens (URL or nodeId). Facts keyed <feature>.exports, <feature>.assets and <feature>.imports take precedence, including explicit empty lists; protectedFiles is preserved when supplied. When absent, drafts infer exports from owned routes and detected src/app or apps/*/src/app directories, assets from owned screen/export facts, and imports from sharedParts using components/layout for Header/Footer/Nav and components/common otherwise. Inferred entries carry inferred:true and evidence. Multiple apps require route/app evidence; unresolved app ownership is not guessed. Workers escalate to supervisor by default (unitQuestions: supervisor|worker).

Data mappings infer candidate entities and list/get/create/update/delete operations from feature and screen names/parts. Repeated components (at least three), form controls and dynamic route segments add operationEvidence; formFields records matched and unmatched ERD candidates. Endpoint contract drafts carry method/path, list queryParams and ERD request/response fields through confirm, split and worker briefs. Resource paths pluralize the final entity-name word and replace underscores with hyphens; conventional paths remain drafts requiring API confirmation. List evidence supplies pagination (page, pageSize with size alias), sort allowedKeys, search q and entity-backed filters. Write request fields include rules for required, maxLength, email/phone/url, consent const:true and enums. DELETE has no response fields.

Data features need apiWiring operationId bindings. Status checks actual HTTP operations in openapi.json and reports contractMissing and contractMatches. Contract matching normalizes field spelling (case, underscores and hyphens) while reporting openapiName, matches structural path parameters and trailing slashes, and reports an unambiguous common API prefix. It checks path-level and operation-level query parameters with local refs and only in:query entries. Request/response comparison resolves local refs, allOf/oneOf/anyOf, arrays and list wrappers (items/data/results), plus JSON, multipart/form-data and application/x-www-form-urlencoded bodies. Type, format, nullable and required mismatches are reported with field-specific reasons. This is static contract evidence, not proof of runtime wiring.

After confirm never wait: defer recommendations and continue, assume at the end. status reports ERD Mermaid, unit DAG/states, decisions, shared-change requests and backend prerequisites. Missing/deferred API bindings and contractMissing entries remain blockers; unitUpdates record supervisor verification. State: .devup/project-plan.json. Follow /devup for backend commands, latest-first dependencies, exact layout/visual audits, orchestration and zero-drift completion.
