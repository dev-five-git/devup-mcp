[devup-mcp 개선 제안 #005] 원샷으로 끝나지 않고 여러 턴이 걸린 원인과 개선안

배경: 견적문의 화면 1개를 구현하는 데 헤더/로고/칩 크기/아이콘/체크 모양/reCAPTCHA 가 턴마다 뒤늦게 발견됨.

원인과 개선안
1. 공통 컴포넌트(GNB) 인식 부재
   - 증상: 시안의 GNB 가 화면마다 달라(5메뉴 vs 7메뉴) 어느 쪽이 정답인지 알 수 없었음. 코드는 화면 단위로만 생성됨.
   - 개선: 같은 인스턴스/컴포넌트 마스터를 쓰는 노드를 식별해 "공통 컴포넌트 후보"로 보고하고,
     화면 간 variant 불일치(메뉴 개수/라벨 차이)를 경고(reviewChecklist)로 노출. 사이트 전체에 적용할지 질문하도록 유도.
2. 정적 마크업만 생성 (002 와 동일)
   - 링크/활성 메뉴/버튼 동작/폼 상태가 없음. 인터랙션 후보를 역할(link/button/tab/checkbox/radio)로 태깅하고
     프로토타입 reaction, 컴포넌트 variant(active/disabled/selected)를 tsx 에 반영.
3. 에셋 내보내기 실패 (003/004)
   - 로고를 못 받아 기존 로고로 대체되어 불일치가 끝까지 남음. fallback 과 정확한 실패 사유 필요.
4. 시안에 포함된 외부 위젯 미인식
   - reCAPTCHA 위젯 이미지를 일반 이미지/프레임으로만 보고 누락. 레이어명/모양으로 "서드파티 위젯 후보"
     (reCAPTCHA, 지도, 결제 등)를 감지해 구현 체크리스트에 올릴 것.
5. 상태/세부 스타일 누락
   - 칩 border/radius/패딩, 체크박스가 원형인지, 쉐브론이 outline 인지 등은 구현 후 비교에서야 드러남.
   - 개선: export 결과에 "상태 변형(selected/disabled)"과 아이콘 종류(filled/outline)를 명시하고,
     devup_visual_compare 를 export 직후 자동 제안(스크린샷 렌더 환경 가이드 포함)해 첫 턴에 차이를 보고하게 할 것.
6. 프로젝트 맥락 부재
   - 이미 있는 Header/Footer, 라우트 존재 여부, .env 키(reCAPTCHA)를 읽지 않음. devup_project_context 의 ui 스코프 결과를
     export 응답에 병합해 "기존 컴포넌트 재사용 vs 신규" 를 처음부터 제안.
7. 모호한 시안 처리
   - 모호하면 추측하지 말고 첫 응답에서 질문 목록(예: GNB 정답 버전, 로고 버전)을 한 번에 반환.

기대 결과: 한 번의 export + 한 번의 비교로 위 항목이 체크리스트에 모두 나와 1~2턴 내 수렴.
